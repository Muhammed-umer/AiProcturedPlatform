Project Scope

Online Test Platform

A department-hosted examination system with two panels. Staff build and analyse tests, students take them under a locked screen with a countdown. Everything runs on our own college server.

Admin Panel

What staff can do.

  1. Create student accounts from an Excel sheetUpload a file containing roll number, name and email. An account is created for every row with a default password, and a printable list is generated to hand out.
  2. Reset any password from the panelTakes a few seconds. This replaces email-based recovery, which cannot work on an offline network.
  3. Create a test with a title and a durationThe duration set here becomes the countdown on the student screen.
  4. Split a test into sectionsSection A, Section B, and so on, or named by topic. This is what makes topic-wise analysis possible afterwards.
  5. Add questions and choose the typeMultiple choice with one answer, multiple choice with several correct answers, or fill in the blank. The form changes to suit the type selected.
  6. Set marks per section, override per questionOne value covers every question in a section. Any single question can be given a different mark, so a two-mark question can sit among one-mark ones. Negative marking is optional.
  7. Upload questions in bulkExcel works exactly and offline. Word and PDF are also accepted, with a review screen where staff correct anything the extraction got wrong before saving.
  8. See results and rankingsA ranked list per test showing the top performer, the lowest performer, the class average, and the highest and lowest scores.
  9. Analyse performance topic-wiseAverage score per section, so it is immediately visible that the class did well in Section A and poorly in Section B. Also shows how many students got each individual question right.
  10. Export everything to ExcelResults and analysis download as a spreadsheet for records and for sharing with recruiters.

Student Panel

What a student experiences.

  1. Log in with roll numberUsing the default password issued by staff. The student is required to set their own password the first time they sign in.
  2. See assigned tests and start oneThe timer begins only when the student clicks start, and counts down from the duration set by the admin.
  3. Take the test under a locked screenThe browser is forced into full screen. Copy, cut, paste, right-click and text selection are all disabled while the test is running.
  4. Get warned for leaving the testSwitching tabs or leaving full screen is detected immediately and shows a warning. After a set number of warnings the test submits itself.
  5. Submit automatically when time runs outAnswers save continuously as they are chosen, so a browser crash or a power cut does not lose the attempt.
  6. See the scoreDisplayed after submission, with a section-wise breakdown if staff choose to release it.

Database and Hosting

Where everything is stored.

  1. PostgreSQL running on the college local serverQuestion banks, student accounts, tests, answers and results all live in one database on a machine inside the department.
  2. No internet needed during a testStudents reach the application over the college network. If the campus connection drops mid-drive, nothing stops.
  3. Student data never leaves the campusRoll numbers, emails and marks stay on our own hardware rather than a cloud service.
Why local PostgreSQL instead of Supabase

The hosted version of Supabase needs an internet connection, which would lock every student out mid-test if the campus link fails. Self-hosting it means maintaining roughly eight containers. Plain PostgreSQL is a single service that any faculty member who knows SQL can read.
